# 5 R9 3090 INT4 FLUX Fill 상주 (rtx3090, 병행)

- 요구사항: [REQUIREMENTS.md](../REQUIREMENTS.md) 4.4 「5. R9」. 정오표 E3·E4·E5·E6·E11.
- 선행: 0번 승인(main `4e215c0`). 고객사 예외(E6)로 1–4번과 병행한다. **1–4번 일정·검증을 늦추지 않는다.** 제출·승인과 3D 품질 평가는 4번(R8a) 승인 뒤. TRELLIS 쪽은 직전 승인 커밋에 고정.
- 담당: **rtx3090**. 브랜치 `item/05-R9-3090`. 보고서 `docs/reports/05-R9.md`.
- 결과 유형: 변경(인페인팅 이미지가 바뀐다). 토글 `VHL_R9=1` 일 때만 새 경로, 기본 꺼짐.

## R-1 가중치

- INT4 transformer: `nunchaku-ai/nunchaku-flux.1-fill-dev`(요구사항서 지정). 나머지(T5·CLIP·VAE·설정): FLUX.1-Fill-dev. **미러 경로로 착수해도 된다**(E11, 미러 = 원본 sha256 동일). 원본으로 받을 수 있으면 원본을 쓴다(토큰 있음). 쓴 저장소·snapshot·파일 sha256 을 기록한다.
- env: 기존 `flux-fill` env(nunchaku 1.2.1, torch 2.9.1+cu128) 재사용 가능(별도 venv 요건 충족). 바꾸면 버전을 적는다.

## R-2 상주 워커 `services/rtx3090_inpaint/`

- 프로세스 1개가 모델을 한 번 올리고 HTTP 로 요청을 받는다. 호출마다 subprocess 를 띄우지 않는다. 포트 `INPAINT_PORT`(기본 8082), **localhost 바인딩**(E4: 오케스트레이터만 호출).
- 입력: 원본 렌더(사용 시점 1장), 2D 마스크, 프롬프트, 시드(기본 0). 출력: `2d_render.png`·`2d_mask.png`·`2d_edit.png`(+ 각 sha256, 시간).
- **마스크 밖 합성:** `2d_edit` 의 마스크 밖 픽셀은 원본 렌더로 덮는다(2진 마스크, 경계 페더 없음). 합성 전·후 이미지를 둘 다 저장해 차이를 보고한다.
- 설정: 1024², 50스텝, guidance 30(기존값). 해상도·스텝 변경은 6번 E4.
- 큐: 한 번에 하나, 나머지는 대기. 상태 조회 엔드포인트.

## R-3 3090 VRAM

- INT4 FLUX 상주 + Z-Image-Turbo(0번 B-3 피크 21.67 GiB) 동시 상주 가능 여부를 실측한다. 넘으면 (a) 생성 요청 때만 교대 로드, (b) Z-Image 4-bit 중 하나를 시간·VRAM 수치와 함께 제안한다. 편집 인페인팅이 우선이다.

## R-4 비교 (같은 입력·같은 시드)

- 입력: 00s ② 의 트랙 A 6건 편집 시점 `2d_render`·`2d_mask`·프롬프트(A5000 이 `xfer/` 브랜치로 보낸다 — 직접 전송이 열리면 그쪽). 트랙 B 중 FLUX 로 만든 건이 있으면 포함.
- 기준: 같은 건의 A5000 bf16 FLUX(CPU offload) `2d_edit`(00s ② 동결본, seed 0).
- 보고: 인페인팅 시간(적재 1회 / 호출당), VRAM, 마스크 안 PSNR·LPIPS·CLIP-T(프롬프트), 마스크 밖 합성 후 원본 일치 여부, 6건 비교 시트(육안).
- 3D 편집 품질(TRELLIS 로 돌린 결과)은 4번 승인 뒤 한다(E6). 이 단계에서는 이미지까지만.

## R-5 오케스트레이터·계약 (설계만)

- E4 (가)안: 3090 오케스트레이터가 A5000 렌더 요청 → 로컬 인페인팅 → 이미지 3종 + 렌더 해시로 편집 요청. A5000 렌더 엔드포인트는 4번 R8a 범위라 **여기서는 구현하지 않는다.**
- `services/common/` 에 HTTP 규약 초안(렌더 요청·응답, 인페인팅 요청·응답, 편집 요청 multipart 필드 `2d_render`·`2d_mask`·`2d_edit`·렌더 해시·base_version, 4xx 사유 코드)을 문서로 둔다. ai-ar-v3 계약 변경 제안의 바탕이 된다. chief 가 검토 후 main 에 먼저 병합한다.
