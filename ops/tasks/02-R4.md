# 2. R4 mesh 만 디코딩 → `.cbin` 직행 + 렌더 입력 교체 (a5000)

- 요구사항: [REQUIREMENTS.md](../REQUIREMENTS.md) 4.4 「2. R4」, 6장 구간 7·「동등성 허용치」 보존 영역 청크. 0번 R11. 정오표 E13·E14·E15.
- 선행: 0-1 승인(PR #11). 순서: 1 E2a → 보조 DS → **2 R4**. DS 가 끝나기 전에 착수하면 Stage 2 비트 비교 대신 아래 R-3 의 "같은 slat_tgt 재디코딩" 방식만 쓴다.
- 담당: **a5000**. 브랜치 `item/02-R4-a5000`(main 에서 분기). 보고서 `docs/reports/02-R4.md`.
- 비교 기준: E2a 채택 상태(editcore 15/15, 정오표 E20). 바닥값은 E2a c15 r1–r3.
- 결과 유형: **SLat 동일, 표시 변경.** 토글 `VHL_R4=1`(기본 꺼짐: 기존 GLB 출력).
- 하지 않는 것: `.cbin` 포맷·계약 변경(conformance 53/53 유지), HTTP 서비스(4번 R8a), 조건 렌더 시점 축소(3번 R10a), 디코더 자체 변경.

## R-1 구현

- `editcore/export.py`: 토글이 켜지면 `decode_slat(slat_tgt, ["gaussian", "mesh"])` + `to_glb` + GLB 저장 대신
  1. `decode_slat(slat_tgt, ["mesh"])` 만 호출 (Gaussian 디코더를 부르지 않는다 — 로그로 확인)
  2. `MeshExtractResult` 의 vertices·faces·vertex_attrs → `deltacontract.partition.split_trellis_vertex_attrs`(기본 `0_1`) → `albedo_to_rgba8` → `partition_mesh` → `chunkbin.encode` (ai-ar-v3 `19ed91f`, 읽기 전용 import)
  3. 청크별 `.cbin` 과 manifest 를 출력 디렉터리에 쓴다. 파일 입출력은 `export` 에만 둔다.
- 좌표: 디코더 native 공간 그대로. `to_glb` 의 회전을 걸지 않는다(D9-b). `partition_mesh` 는 NORMALIZED [-0.5, 0.5] 를 요구하므로 `assert_in_normalized_bounds` 를 통과하는지 확인한다.
- 디버그·렌더용 GLB 는 `server/glbbuild.py`(`build_glb`) 로 `.cbin` 에서 조립한다.
- **R11 승계 (2026-10-26 chief 정정):** 요구사항서 4.4 0번 R11 은 "**점유 비교**로 바뀐 청크를 정하고 나머지는 부모 `.cbin` 바이트를 승계"다. 기존 서비스(`legacy/a5000/edit_service/api/ops.py:96-117`)는 마스크 ∪ halo 부기만 쓴다 — 마스크 밖에 새로 생긴 셀(R_keep 신규, 예: A-S1)이 있는 청크도 부모 바이트로 덮여, 저장 SLat(`slat_tgt`)과 화면 청크가 어긋난다.
  - 변경 청크 = **부기(마스크 ∪ halo 가 닿는 청크) ∪ 점유 변경 청크(그 청크 안 SLat 점유 셀 집합이 부모와 다른 청크)**. 나머지는 부모 바이트 승계. 해시로 정하지 않는다.
  - 보고: 시나리오별 청크 수, 부기 청크 수, 점유 변경으로만 추가된 청크 수(= 마스크 밖 생성이 화면에 반영되는 청크), 승계 청크 수.
  - 이미 돈 GPU 실행은 다시 돌리지 않는다. 저장된 slat_tgt·디코딩 메시로 청크 분할·변경 집합만 CPU 로 다시 계산한다.

## R-2 렌더 입력 교체 (분리 불가, 4.4)

- 다음 편집의 조건 렌더(포크 Blender 렌더러)는 GLB 를 입력으로 받는다. R4 이후 입력은 `glbbuild` 로 조립한 **정점색 GLB** 다.
- Cycles 재질이 정점색을 읽는지 확인한다: 같은 시점에서 (a) 기존 텍스처 GLB 렌더 (b) 정점색 GLB 렌더를 나란히 보고, (b) 가 회색이면 실패로 멈추고 보고한다. 재질 설정을 바꿔야 하면 포크를 고치지 말고 래퍼(`editcore/render.py`) 쪽 처리로 하고 방법을 적는다.
- 비교: 14건 각 편집 시점 1장씩 (a)·(b) 렌더의 픽셀 차이(RGB max·mean)와 2D 마스크 차이, 육안 시트.

## R-3 검증

1. **디코딩 앞단 불변(slat_tgt):** 토글 켬/끔 각 1회에서 slat_tgt 를 저장해 coords 완전 일치·보존 셀 비트 동일·편집 셀은 E14·E15 로 판정. 추가로 **같은 저장 slat_tgt 하나**를 두 경로로 디코딩해 비교한다(Stage 2 비결정성과 분리).
2. **mesh 디코더 동일성:** 같은 slat_tgt 에서 `["mesh"]` 단독과 `["gaussian","mesh"]` 의 mesh 출력(정점·면) 비트 동일 여부, 같은 호출 2회의 동일 여부.
3. **청크:** 청크 수, 변경 청크 수(부기), 승계 청크 바이트 동일(부모 대비), 변경 청크 바이트 합, 청크별 면 수(부모·자식), `.cbin` 디코드 왕복(정점 수·면 수·단위 법선 비율).
4. **메시 밀도:** 단순화가 빠지므로 면 수가 늘어난다. 14건의 GLB(기존) 면 수 vs `.cbin` 전체 면 수, 변경 청크 바이트를 표로 적는다. E13 의 B1 면 수 차이(`to_glb` mincut 두 갈래)가 R4 경로에서 사라지는지도 적는다.
5. **테스트:** conformance 53/53, ai-ar-v3 서버 360 passed, CPU 테스트, `.cbin` 을 ai-ar-v3 `contract` 디코더로 읽어 manifest 와 일치.
6. **Unity:** 이번에는 하지 않는다(사용자 2026-10-25: Unity 는 나중에 App 서버와 함께). 요구사항서 4.4 R4 의 「Unity 육안 비교, `unity_inplace_check.sh`」와 「Unity 프레임 시간」은 보류로 보고서에 적는다.

## R-3a 고객사 추가 보고 (정오표 E21, 2026-10-26)

- E15 상한 = 현재 기준(15 스텝) 기준–기준 mean 최댓값 × 1.2 = 4.06e-3. 보고서에 공식과 값을 적는다.
- 시나리오별 표: R4–기준 mean\|Δ\|(3쌍) | 기준–기준 mean\|Δ\|(3쌍) | 편집 셀 수. R4 는 샘플링을 바꾸지 않으므로 두 분포가 같아야 한다. 3.2e-3 을 넘은 쌍이 있는 시나리오를 편집 셀 수와 함께 명시한다.
- **DS 로 Stage 2 비트 비교:** DS 는 구현·검증 완료(PR #17). `VHL_DS_DETERMINISTIC=1` 로 **한 프로세스 안에서** 같은 시나리오를 R4 끔 1회 → R4 켬 1회 실행해 slat_tgt(coords·feats 전체)와 Stage 1·2 캐시 다이제스트가 비트 동일인지 14건 모두 확인한다(프로세스가 다르면 spconv 때문에 갈릴 수 있으므로 반드시 한 프로세스). 운영 기본값(DS 꺼짐)은 바꾸지 않는다.

## R-4 예상 (실행 전에 먼저 적는다)
