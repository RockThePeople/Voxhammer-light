- 장비: a5000 (RTX A5000 24 GB). 브랜치 `item/04L-link-a5000`(`item/02-R4-a5000` `60c951d` = 경계 스냅 포함에서 분기, main `2eb9ed4` 병합).
- 지시: 사용자 2026-10-26 10:18, `ops/tasks/04L-link.md`. 범위 = R8a A절(상주 워커·렌더·편집 엔드포인트) + R-7 종단(3090 과 함께).
- 워커: `services/a5000_edit/`(app·engine·store·jobs·seed·run.sh·tests). `VHL_R4=1`, editcore 기본 15/15(E20).

## 0. 연결 시험 (구현 전, 2026-10-26 10:20)

- A5000 에 임시 리스너를 띄웠다: `python3 -m http.server 8082 --bind 0.0.0.0` → `0.0.0.0:8082 LISTEN`.
- A5000 안에서 공인 주소 `http://117.16.244.35:8082/` 로 접속하면 성공한다.
- firewalld 는 켜져 있다(active). 8082 가 열렸는지는 sudo 권한이 없어 확인하지 못했다.
- **3090 → A5000:8082 결과는 3090 의 curl 로 확인 대기다.** 막혀 있으면 관리자가 `firewall-cmd --add-port=8082/tcp --permanent && firewall-cmd --reload` 해야 한다.

## 1. 예상 (실행 전, 2026-10-26)

- **로드:** 시작 때 1회 약 30 s(0-1 CLI 구간 8 실측 33–34 s 와 같은 모델 집합). 요청당 로드는 0 이다.
- **구간 1(조건 렌더):** 포크 렌더러를 별도 프로세스로 부르므로 약 26 s(0번 실측 25.7 s, A-M1)에 bpy import 몇 초가 더해진다.
  - 요청 시점 1장만 돌려주지만 렌더는 5시점 × 2(원본·마스크) 그대로다.
- **구간 3–7:** CLI(c15 + R4 정정 규칙)와 같다. 3–6 은 약 41 s, 7 은 2–5 s(R4 3-1 실측 평균 2.24 s, 경계 스냅 비용 조금 더함).
  - 첫 요청은 CUDA 커널 준비로 몇 초 더 걸릴 수 있다.
- **같은 입력 3회(한 프로세스):**
  - coords·보존 셀은 비트 동일이다.
  - 편집 셀은 DS 꺼짐이라 `SparseDownsample` 원자적 덧셈 때문에 회차마다 1e-2 수준으로 다를 것이다. 이는 같은 프로세스여도 생기는 기존 비결정성이다(E22 기록용).
  - 2·3회차 RSS·VRAM 은 1회차 직후 수준으로 돌아온다(편집 뒤 캐시 해제).
- **트랙 A 6건 워커 vs 동결 CLI(c15 r1):** coords·보존 셀 필수 통과, 편집 셀 E14·E15(E21) 분포 안.
- **시점 자동 선택:** 규약 규칙(마스크 셀 투영 면적, 가림 무시)이 동결 편집 시점(렌더된 2D 마스크 화소 최대, 가림 반영)과 다른 건이 있을 것이다. 투영 면적이 비슷한 건(A-C1)과 가림이 큰 건(A-S2 코)이 그렇다.

## 2. 구현 (코드확인)

- **`services/a5000_edit/app.py`(FastAPI)** — 경로·응답·오류 본문은 현행 서비스(`legacy/a5000/edit_service/api/routes.py`)를 따른다.
  - `POST /v2/trellis/render`: 계약 3.28.0 `BRenderRequest/Response`. GPU 큐를 지나 동기로 응답한다. `render_id` 기록은 `RUNS_DIR/04l/renders/<id>/record.json` 에 24 h 남고 재기동해도 유지된다. 두 해시와 마스크 지문을 남긴다.
  - `GET /v2/trellis/renders/<id>/2d_render.png`·`2d_mask.png`.
  - `POST /v2/trellis/edit`(multipart `meta` + 3장): 다음 순서로 검사한 뒤 편집 잡을 큐에 넣는다.
    1. 조건 3장 유무(422)
    2. PNG·1024²(400)
    3. `render_id` 기록(404, 만료 포함)
    4. 받은 바이트·meta 해시 vs 기록(409 `RENDER_MISMATCH`)
    5. 마스크 지문 vs 렌더 때
    6. 멱등 재생
    7. base_version(409)
  - `GET /v2/trellis/jobs/<id>`(BChunkResponse), staging 청크, 커밋 판본 청크, commit: 현행과 같은 모양이다. `GET .../assets/<id>/v<n>/manifest.json` 은 04L 보조다.
  - 오류 코드 4종(`CONDITION_IMAGES_REQUIRED`·`RENDER_MISMATCH`·`RENDER_UNKNOWN`·`BAD_CONDITION_IMAGE`)은 고정 계약(19ed91f)에 아직 없다. 그래서 같은 기반 클래스(`DeltaContractError`)로 정의했다. 코드·상태는 ai-ar-v3 PR #27(3.28.0)과 같다.
- **`engine.py`:**
  - `load()`: `editcore.models.load_pipeline()`(TRELLIS-image-large 전체: 두 flow, SS 인코더·디코더, SLat 디코더, DINOv2)을 1회 실행하고 로드 시간·메모리를 기록한다.
  - `edit()`: 요청마다 `torch.inference_mode()` 로 다음을 한다.
    - 부기 선행 계산
    - editcore 편집(W34 입력 = 부모 판본 `slat.safetensors`)
    - R2 SLat 저장
    - `decode_to_cbin`(부기 ∪ 점유 변경 ∪ 신규, R11 승계, 경계 스냅, manifest uri 는 to_version)
    - 구간별 계측(reference.meter)
    - 결과·캐시를 놓고 `torch.cuda.empty_cache()`(계측 밖)
  - `render()`: 렌더 입력 메시를 정한다. 생성 판본 = `model.glb`(텍스처). R4 판본 = `.cbin` → glbbuild 정점색 GLB → 판본 정규화 → (iv) 보정. 그다음 `editcore.render.render_condition`.
- **`editcore/render.py`:**
  - `render_condition(mesh, mask_cells, view, *, xf, out_dir)` 한 함수로 감쌌다(나중에 R10a 를 끼울 자리). 마스크 GLB(셀 노출면, s5_masks 와 같은 변환) → 포크 렌더러(0번 래퍼, 수정 없음, EXR 은 bpy 프록시) → 요청 시점 1장 + 2D 마스크.
  - `choose_view`/`mask_area_per_view`: 마스크 셀(halo 전)을 5시점 카메라로 투영한 면적(256² 래스터, 가림 없음), 최대, 동률이면 낮은 번호.
- **`store.py`·`jobs.py`:** 현행 서비스 코드를 그대로 이식했다(출처 주석). 저장소 기본 경로만 `RUNS_DIR/04l/store` 로, 잡에 큐 대기 시간을 더했다.
- **`seed.py`:** 트랙 A 생성 자산을 v1(커밋됨)으로 넣는다. `vhl-ta-moto`(458 청크), `vhl-ta-snowman`(610), `vhl-ta-chair`(467).
- **테스트 `services/a5000_edit/tests/test_worker_cpu.py`(GPU 없이) 9 passed:** 인증, JSON 본문 거절(422), 이미지 빠짐(422, detail.missing), PNG·크기(400), render_id 없음·만료(404), 해시 불일치(409), base_version(409, edit·render), view 범위(422), 모르는 경로(404 NOT_FOUND), 시점 규칙.
